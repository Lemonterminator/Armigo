# 等待夹稳规则：独立验证协议 v1（2026-11-23）

写于运行之前，没有看过 val2 上的任何结果。

## 1. 背景与改动

首次 grasp 末段 A/B 实验的结果见 `E:/scratch/grasp-tail-ab/20261123-075031/REPORT.md`，协议见 [GRASP_TAIL_AB_HANDOFF_2026-11-23.md](GRASP_TAIL_AB_HANDOFF_2026-11-23.md) r3。在 val 的 60 个布局上，A+wait 相对 A：

- 首次夹稳 +22/60，22:0；
- 抬升 +9；
- 分拣 +8，8:0；
- 碰撞布局 +1：一次抬升时夹爪与环境接触 2 帧，峰值 3.4 N。

按那份协议第 5 节的规则，碰撞布局增加，因此要求把等待夹稳作为独立的工程改动，在新的布局集上另行验证。本协议就是这次验证。

**改动内容。** `StudentTwin(clamp_wait=True)`，评测参数为 `--clamp-wait`，代码在 [student_rollout.py](../../src/digital_twin_armigo/agent/student_rollout.py)。

- 只要 ACT 在**任一** grasp 段（包括重试）给出 `done` 时夹持尚未确认（连续 4 帧双爪受力 ≥ 1.5 N 且砖速 < 5 mm/s），就保持最后一条已执行命令，直到出现以下任一情况：
  - 夹稳且静止；
  - 夹爪监测为 BLOCKED；
  - 保持满 45 帧（超时）。
- 判据和帧数沿用专家的 `_close_and_clamp`。不增加其他动作。
- 每次等待在 `events.jsonl` 里写一条 `clamp_wait` 事件，记录帧数和结果。

**与 A/B 实验中 A+wait 的区别。**

- A+wait 只在首次 grasp 触发切换时等待。
- 本规则不看切换判定，并且覆盖重试的 grasp 段。
- 首次 grasp 触发切换时，两者的命令逐字节相同（`tests/test_grasp_tail.py`）。

`TakeoverTwin`（DAgger 采集）暂不支持此规则，传入会直接报错。

## 2. 布局、模型与参数

- **布局：** `config/vla/val2.json`，100 个布局，种子 1400001–1400100。
  - 生成命令：`make_suites.py --val 100 --val-start 1400001`。
  - 与 train、val、test 以及 agent_bench 的种子都不重叠。
  - 类别比例与其他套件相同：正常 34，缺陷面 0–5 各 11。
  - 在此之前从未用于任何模型或规则开发。
- **模型：** `E:/scratch/s11v2-fit30k/best`，与 A/B 实验相同。
- **参数：** 与 A/B 实验相同。
  - `--device cuda --mode sync --replan-interval 50 --no-teacher`
  - 判别器 `results/agent-bench/sup-v7bot-local.json`
  - 评分参考 `E:/scratch/vla-pilot-grader_reference_frozen.json`
  - `sensing=realistic`

## 3. 三次运行

三次运行都带 `--grasp-tail-mode act`（只插桩，不改动作）和 `--protocol clamp-wait-v1`。

| 组 | 额外参数 | 含义 |
| --- | --- | --- |
| **A** | `--record-act-rgb` | 原始 ACT，记录每次 ACT 请求的 RGB |
| **W** | `--clamp-wait --pin-rgb-from <A>` | 等待夹稳规则 |
| **A′** | `--pin-rgb-from <A> --pin-handoff clamp-wait` | 重复 A，作为噪声基线 |

先跑 A，然后跑 W 和 A′。

**共享前缀。** 沿用 r3 的 RGB 固定，见 [rgb_pin.py](../../src/digital_twin_armigo/vla/rgb_pin.py)。

- W 和 A′ 的交接帧都定在 A 首次 grasp 中 ACT 给出 `done` 且尚未夹稳的那一帧（`handoff_frame("clamp-wait")`），不看切换判定。
- A 在 `done` 时已经夹稳的布局，整回合都固定。之后如果在重试的 grasp 上才出现差异，会记为请求失配并从那里转为实时，逐例列出。
- 因此，A′ 衡量的是与 W 同一前缀、同一交接点之后实时运行的波动。

## 4. 终点与统计

**终点：**

- 主要终点：首次 grasp 夹稳的布局数 / 100。
- 次要终点：
  - 完成过抬升 / 100；
  - 最终分拣成功 / 100；
  - 发生碰撞的布局数 / 100，并拆分为机械臂与环境、夹爪与环境两类，报告峰值力；
  - 抬升转化：新增的首次夹稳中，同时新增抬升的布局数。
- 规则遥测：等待次数、各结果（夹稳 / 阻挡 / 超时）的计数、等待帧数，首次 grasp 与重试分开统计。

**统计方法：** 两组配对，A vs A′、A vs W。每组给出四格表、净差、95% bootstrap 区间（10,000 次，种子 42）和双侧精确 McNemar p 值，方法与 A/B 实验相同。

**前缀核验：** 从开头到交接帧，命令须逐字节一致。请求失配的布局逐例列出。

**命令：**

```
python scripts/vla/clamp_wait_report.py --out <root> --run act=<A> --run act-rep=<A′> --run clamp-wait=<W>
```

## 5. 预先约定的判定

| 条件 | 判定 |
| --- | --- |
| 数据完整，前缀核验通过；W − A 首次夹稳净增 ≥ 10/100；抬升和分拣的净差都 ≥ 0；碰撞布局净增 ≤ 2/100；没有新增机械臂与环境接触的布局 | 把 `clamp_wait` 设为学生评测的默认行为，并在 `TakeoverTwin` 中接入同一规则 |
| 首次夹稳达到阈值，但抬升或分拣减少，或碰撞条件不满足 | 逐例检查新增的碰撞和下游失败，报告收益与代价，暂不设为默认 |
| 首次夹稳净增 < 10/100，或与 A′ 噪声同量级 | 不设为默认；报告差值、区间和超时布局 |

关于阈值的说明：

- 10/100 约为 A/B 实验中 +22/60（37 个百分点）的四分之一，是本轮的工程取舍。
- 碰撞允许 +2，是因为 A/B 实验中，新增的碰撞来自原本没有走到的抬升，属于短时的夹爪轻碰。阈值在运行前定下，不按结果调整。
- 验证只覆盖这 100 个布局。碰撞事件稀少，没有新增碰撞也不能证明风险相同。

# v2：等待中的阻挡退出（2026-11-23）

写于 val3 运行之前，没有看过 val3 上的任何结果。v1 的 val2 结果见 `E:/scratch/clamp-wait/val2-20261123-093057/REPORT.md`，本节的规则和判据是看过 val2 之后定的，因此只能在新布局上判。

## 6. 改动

v1 在 val2 上的判定是 inspect_costs：首次夹稳 +45（45:0），抬升 +28，分拣 +20（21:1），但碰撞布局 +4，超过 +2 的上限。逐例检查发现两类代价：

- 规则本身：等待超时期间夹爪一直压着环境（1400044，两次各 45 帧，接触时长从 A 的 111 帧拖到 200 帧）；
- 走得更远：更多回合走到抬升和放碗，新增的 4 个碰撞布局都发生在夹稳之后的抬升或后续重抓（val2 上逐例的首次接触见 `clamp_wait_report.py` 的 `new_collision_attribution`），不在等待期间。

v2 只修第一类，加一个**阻挡退出**：`StudentTwin(clamp_wait=True, clamp_wait_obstruct_rad=0.05)`，评测参数 `--clamp-wait --clamp-wait-obstruct 0.05`。

- 等待期间保持的命令不变。如果连续 3 次观测（`CLAMP_WAIT_OBSTRUCT_FRAMES`）中机械臂关节 j0–j4 与保持命令的最大偏差都 ≥ 0.05 rad，说明机械臂被东西顶住了，等待以 `obstructed` 结束。之后的处理与超时相同：未夹稳，走 no_clamp 分支。
- 判定顺序：阻挡（BLOCKED）> 夹稳 > obstructed > 超时。同一帧既夹稳又满足 obstructed 时算夹稳。
- 只用关节测量值和自己发出的命令，不用仿真里的接触力真值，`sensing=realistic` 下可用。
- `clamp_wait` 事件多记一项 `arm_err_max`。

**阈值来源（val2 的 W 组，70 次等待）：** 1400044 的两次等待全程夹爪–环境接触，关节偏差 0.085–0.11 rad；1400016 一次重抓有 2 帧接触，偏差 0.066 rad，但第 2 帧就夹稳了；其余 67 次没有接触，偏差都 ≤ 0.028 rad。0.05 rad 取在两组之间。按 val2 回放推算，v2 只会改变 1400044 的两次等待（约 2 帧后退出），其余等待结果不变。

- **布局：** `config/vla/val3.json`，100 个，种子 1500001–1500100，命令 `make_suites.py --val 100 --val-start 1500001`。与 train、val、val2、test 不重叠，此前从未使用。类别比例同前。
- 模型和参数与 v1 相同（第 2 节）。四组都带 `--grasp-tail-mode act --protocol clamp-wait-v2`：

| 组 | 额外参数 | 含义 |
| --- | --- | --- |
| **A** | `--record-act-rgb` | 原始 ACT |
| **A′** | `--pin-rgb-from <A> --pin-handoff clamp-wait` | 噪声基线 |
| **W1** | `--clamp-wait --pin-rgb-from <A>` | v1 规则 |

- 每次等待期间的夹爪–环境接触帧数（接触力 > 2.0 N，与冻结的评分参考 `max_jaw_env_contact_n` 一致）；

## 9. 预先约定的判定（v2，A vs W2）

安全判据改为**按归因判定**（2026-11-23 与用户确认）。

| 条件 | 判定 |
| --- | --- |
| 数据完整，A 与各组的前缀核验通过；首次夹稳净增 ≥ 10/100；抬升和分拣净差 ≥ 0；没有新增机械臂–环境碰撞的布局；W2 的每一次等待期间夹爪–环境接触 ≤ 5 帧 | 把 `--clamp-wait --clamp-wait-obstruct 0.05` 设为学生评测的默认行为，并在 `TakeoverTwin` 中接入同一规则 |
| 首次夹稳达到阈值，但其他条件有不满足的 | 逐例检查，报告收益与代价，暂不设为默认 |
| 首次夹稳净增 < 10/100，或与 A′ 噪声同量级 | 不设为默认 |

说明：

- 碰撞布局总数照样报告。净增超过 +2 时，逐例列出新增布局的首次接触位置，但不作为否决条件。理由：val2 上新增的碰撞来自原本走不到的抬升和放碗，不是等待动作造成的。这是放宽，代价是"走得更远"带来的碰撞不再拦住这条规则，需要另行处理（抬升和放碗的精度）。
- W1 vs W2 只作描述，不参与判定。预期两组几乎相同，只在有阻挡的等待上不同；如果 W2 的首次夹稳比 W1 少超过 2 例，报告中要逐例说明。
- 100 个布局里碰撞事件很少。没有出现问题不能证明风险相同。

# v3：等待中的合拢退出（2026-11-23）

写于 val4 运行之前，没有看过 val4 上的任何结果。v2 的 val3 结果见 `E:/scratch/clamp-wait/val3-20261123-132909/REPORT.md`。本节的规则和阈值是看过 val2、val3 之后定的，这两组只作开发数据，判定只看 val4。

## 10. 改动

v2 在 val3 上的判定是 inspect_costs：收益重现（W2 − A：首次夹稳 +36，抬升 +26，分拣 +18），但阻挡退出一次都没触发。1500010 的两次等待各 45 帧都压着桌面（15–19 N），关节偏差只有 0.015–0.023 rad，和正常等待重叠。这类接触的共同点是夹爪已经合空：两爪之间没有砖。

v3 把阻挡退出换成**合拢退出**：`StudentTwin(clamp_wait=True, clamp_wait_empty_rad=0.03)`，评测参数 `--clamp-wait --clamp-wait-empty 0.03`。

- 等待期间保持的命令不变。如果连续 3 次观测（`CLAMP_WAIT_EMPTY_FRAMES`）中夹爪位置 `q[5]` 与保持的夹爪命令之差都 < 0.03 rad，说明夹爪已经合到命令位置、中间没有夹住东西，等待以 `empty` 结束。之后的处理与超时相同：未夹稳，走 no_clamp 分支。
- 判定顺序：阻挡（BLOCKED）> 夹稳 > obstructed（v3 不开）> empty > 超时。同一帧既夹稳又满足 empty 时算夹稳。
- 只用夹爪位置和自己发出的命令。不用力矩：`sensing=realistic` 不假设能读舵机负载（`docs/vla/STUDENT_INPUTS.md`）。val2/val3 上加不加"力矩 < 0.5"结果相同。
- `clamp_wait` 事件多记一项 `grip_err_min`。

**阈值来源（val2 的 W 组 + val3 的 W1 组，158 次等待，开发数据）：**

- 夹住砖时，砖把夹爪撑在命令之上。93 次以夹稳结束的等待里，夹爪与命令之差在整个等待期间最小是 0.049 rad（2 次，其余都 ≥ 0.064）。
- 阈值与连续帧数的离线扫描：

| 阈值 / 连续帧 | 夹稳等待被误打断 | 超时等待被提前结束 | 4 次压着环境的等待，退出前的接触帧 |
| --- | --- | --- | --- |
| 0.01 / 3 | 0/93 | 57/65 | 4, 3, 8, 5 |
| 0.02 / 3 | 0/93 | 61/65 | 3, 3, 5, 3 |
| **0.03 / 3** | **0/93** | **64/65** | **3, 3, 4, 3** |
| 0.04 / 3 | 0/93 | 64/65 | 3, 3, 3, 3 |

- 取 0.03：和夹稳等待的最小值 0.049 之间留约 0.02 rad 的余量；0.04 只留 0.009。
- 压着环境的接触在等待开始前就已存在，所以退出最早也要在等待的第 2 帧（3 次观测），每次等待里会留下 2–4 帧接触。
