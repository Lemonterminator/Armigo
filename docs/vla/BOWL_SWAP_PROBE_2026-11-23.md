# 目标碗对照切换：冻结权重诊断协议（2026-11-23）

写于正式运行之前。冒烟测试只用于检查脚本能否跑通，不看结果。

## 1. 问题

val4 新默认（等待夹稳 + 合拢退出 0.03）下，W3 有 24 个回合以“放置未确认”结束。这 24 个回合中，分类和搬运指令都正确，但有 23 个回合的砖落进了另一只碗。按关节角做正运动学复算，刚进入释放段时，这 23 个回合的夹爪都更靠近另一只碗；45 个成功回合则都更靠近目标碗。所以错误发生在 `carry_to_bowl` 段：学生没有把砖送到指令指定的碗上方。

按第一次搬运统计，val4 中要求绿碗、且绿碗在左侧（极角更大）的 11 例里，0 例放对。训练集里碗的左右是平衡的（绿碗在左 151/300），颜色不平衡：导出的示范中粉碗 176 条，绿碗 72 条。

学生看不到碗的坐标。它只能从图像里找到碗，再根据状态向量里的 bowl one-hot（`contract.encode_state` 第 31–33 位）决定去哪只。指令文本 ACT 不读。

要回答的问题：**在同一个状态下只改 bowl 指令，学生的搬运方向会不会跟着变？** 不跟着变时，它固定去的是哪只碗：按颜色固定，还是按位置固定？

## 2. 方法

脚本：[bowl_swap_probe.py](../../scripts/vla/bowl_swap_probe.py)。统计：[bowl_swap_report.py](../../scripts/vla/bowl_swap_report.py)。

- **权重**：`E:/scratch/s11v2-fit30k/best`，与 val2/val3/val4 评测相同，冻结不训练。
- **布局**：主分析用 `config/vla/val4.json` 的 100 个。每个布局只要约 20 秒，所以 val3、val2 各 100 个也照同样方法跑，作为复现；判读以 val4 为准，三组合并的结果只作报告。
- **运行方式**：每个布局按评测默认设置运行学生回合（sync，replan 50，clamp-wait，合拢退出 0.03），直到第一次 `carry_to_bowl`。回合这一次运行是新跑的，所以能否到达搬运段会与 W3 记录略有不同。
- **对照**：在搬运起点保存仿真检查点，然后从同一检查点闭环运行 `carry_to_bowl` 三次，只改 bowl 参数：
  - `req`：回合自己请求的碗；
  - `req2`：同一个碗再跑一次，用来度量渲染和 bf16 推理噪声；
  - `swap`：另一只碗。
- 三次运行之后回合停止，不做释放和评分。
- **记录**：TCP 路径、段末 TCP 和砖的位置、是否掉砖，以及两只碗的真实中心。

## 3. 指标（运行前写定）

段末 TCP 的水平位置离哪只碗的真实中心更近，就记为“去了”哪只碗。离那只碗中心不超过 `BOWL_R` = 0.10 m 时，另记为“到达”。掉砖或段出错的臂单独计数，不参与分类。

每个布局按 `req` 和 `swap` 两臂的去向分为四类：

| 类别 | `req` 去向 | `swap` 去向 | 含义 |
| --- | --- | --- | --- |
| 跟随 | 请求的碗 | 另一只碗 | 指令起作用 |
| 固定 | 同一只碗 X | 同一只碗 X | 忽略指令；再按 X 的颜色、左右（极角大小）、离搬运起点远近细分 |
| 反向 | 另一只碗 | 请求的碗 | 颜色和碗的对应关系搞反 |
| 其他 | 掉砖、出错或无法判定 | | |

报告内容：

1. 四类的布局数；按要求的颜色 × 目标碗左右，列出 `swap` 臂去对碗的比例（2×2 表）。
2. 噪声：`req` 和 `req2` 去向一致的比例，以及两者段末 TCP 距离的中位数。
3. 与原始失败对应：`req` 臂去错碗的布局里，`swap` 臂去了哪只碗。

## 4. 判读规则（诊断用，不是放行门槛）

先看噪声：`req` 与 `req2` 去向一致的比例低于 90% 时，下面的分类都要打折扣，报告时写明。

- **D1 指令起作用**：跟随 ≥ 85%。说明 bowl 编码被用上了，错碗主要来自其他原因，比如闭环搬运偏移或碗定位不准。下一步看搬运控制，即建议中的选项 2（专家接管搬运 A/B）。
- **D2 忽略指令**：固定 ≥ 30%。
  - 固定去的碗里，同一颜色占 ≥ 80%：颜色先验问题，与粉碗示范多有关。下一步做目标编码和颜色配比，包括补“同起点、相反目标”的示范。
  - 固定去的碗里，同一侧或离起点较近的碗占 ≥ 80%：空间默认问题。下一步补左右布局覆盖，加强视觉定位。
- **D3 颜色对应搞反**：反向 ≥ 15%。说明碗颜色的视觉识别有问题。下一步看碗的感知输入和颜色增强。
- 都不满足时，按 2×2 表和逐例结果描述，不强行归类。
